## 最小真实任务

1. 建立全新测试目录，准备简单输入，限制允许修改的文件。
2. 主 Agent 提交带稳定幂等键的任务，保存 task/session/attempt 身份。
3. Worker 通过真实 CLI 执行；记录原生工具事件与结果身份，不能只记录受理状态。
4. 主 Agent 独立读文件并检查内容；需要时提出一次只改指定部分的返工。
5. 核对新轮次、同会话及未要求修改部分的内容，实际通过后才 accept。
6. 对执行中断与不确定提交，只检查并明确恢复决策，禁止为了验收重复投递相同目标。

## 原生账号通路的验收边界

已实现的组合为：随包 IPC 库 → `wb.request/http.fetch` 宿主账号请求 → 带 nonce 的临时本机 HTTP → 独立内置 CLI 的 stdio ACP 工具执行。凭据由宿主管理，CLI 使用独立 profile；这不等于桌面原聊天，也不证明桌面连接器已继承。

CLI 转发白名单精确限定为无 query 的 `POST /v2/chat/completions`，其他模型协议当前不支持，也不静默回退。初始化模型目录的只读请求由网关内部单独处理。

宿主请求约 50 秒、请求和响应各约 640 KiB，采用完整缓冲。长任务、较大输入输出与真实逐任务消耗仍需单独验证，不以当前只读目录结果或定向模拟测试推断长期可用。

网关自身不重派结果不确定的业务目标；底层 CLI 的连接恢复或网络重试不完全由网关控制，不能将本地幂等提交与“不自动重派”说成所有上游请求绝对不重复。
